# CATALOGA — Reference Implementation of a Normative CBOM Minimum-Elements Model

Companion artifact for the paper **"CATALOGA: A Normative Minimum-Elements Model
for Cryptographic Bills of Materials — Enabling Automated, Whole-Infrastructure
PQC Migration"** (paper Sections 3–5, 7.1).

This package turns the paper's three contributions into runnable, testable code:

1. **The C1–C9 minimum-elements model** — a JSON Schema (`schemas/cataloga-schema-v0.9.json`)
   that is a superset of CycloneDX 1.7 CBOM (ECMA-424) and adds the four EXT
   namespaces: `systemContext` (C5), `qvClassification` (C6), `locationProvenance`
   (C4), `canonicalKey` (C9).
2. **The analysis engine** — QV classification (C6), canonical identity and
   deduplication (C9), criticality scoring and migration queue (C5 × C2), and
   cross-element validation (C6 must be derivable from C2; references must resolve).
3. **Discovery connectors + benchmarking** — TLS/certificate, config/IaC, and cloud
   connectors, plus a precision/recall/F1 benchmarking protocol grounded in the
   BF-CBOM finding of "striking discrepancies" between generators.

**Verified: 49/49 tests pass** (6-Oct-2026). The example corpus is generated by the
same engine that validates it, so the shipped examples always conform.

## Layout

```
cataloga-reference/
├── schemas/cataloga-schema-v0.9.json   # the C1-C9 JSON Schema (CycloneDX 1.7 superset)
├── cataloga/
│   ├── schema.py                       # validator: schema + cross-element rules
│   ├── qv_classifier.py                # C6 QV classification engine
│   ├── dedup.py                        # C9 canonical identity + merge
│   ├── criticality.py                  # C5 x C2 scoring + migration queue
│   ├── engine.py                       # discovery -> enrich -> CBOM emission pipeline
│   ├── benchmark.py                    # precision/recall + cross-generator agreement
│   └── generators/                     # tls_scanner, config_scanner, cloud_scanner
├── examples/                           # generated corpus (vran-edge, enterprise-web)
│   └── ground-truth/corpus-v1.json     # ground-truth corpus (paper Section 5.4)
├── scripts/generate_examples.py        # regenerates the corpus with the engine
├── tests/                              # 49 tests, 6 groups
├── cli.py                              # command-line toolkit
├── requirements.txt                    # jsonschema, PyYAML, pytest
└── conftest.py
```

## Step-by-step: how to test and run

```bash
# 1. Go to the package directory
cd .../research_papers/CATALOGA/cataloga-reference

# 2. Create and activate a virtual environment
python3 -m venv .venv
source .venv/bin/activate

# 3. Install dependencies (three, tiny)
pip install -r requirements.txt

# 4. Regenerate the example corpus (optional — verifies generator + validator agree)
python3 scripts/generate_examples.py

# 5. Run the test suite (expect 49 passed)
pytest tests/ -v
```

## CLI usage

```bash
python3 cli.py validate examples/vran-edge-cbom.json            # VALID
python3 cli.py classify RSA RSA 2048                            # classical-112 + NIST IR 8547 notes
python3 cli.py classify PQC ML-KEM 768                          # PQC-ready (FIPS 203)
python3 cli.py dedup examples/enterprise-web-cbom.json          # canonical identities
python3 cli.py queue examples/vran-edge-cbom.json               # migration queue, highest first
python3 cli.py scan-tls example.com --port 443                  # live TLS discovery
python3 cli.py scan-config nginx.yaml                           # config/IaC discovery
python3 cli.py scan-cloud cloud-inventory.json                  # cloud discovery
python3 cli.py benchmark examples/ground-truth/corpus-v1.json examples/vran-edge-cbom.json
```

## Innovation markers (what to point reviewers at)

1. **QV classification engine (C6)** — the machine-readable bridge from inventory
   to migration schedule: every asset gets a NIST IR 8547 classification with the
   exact deprecation/disallowance timeframes. `cataloga classify RSA RSA 2048`.
2. **The schema itself** — the C1–C9 model as normative JSON Schema, closing the
   four gaps the Comcast IETF draft catalogued (hierarchy, criticality scoring,
   duplication, code-only bias) as a CycloneDX **superset, never a fork**.
3. **Cross-element validation** — a CBOM record is invalid unless C6 is derivable
   from C2; the engine and the validator share one code path, so examples cannot
   drift from the schema.
4. **Benchmarking protocol** — precision/recall vs a ground-truth corpus, the
   objectivity instrument that separates "produced a CBOM" from "produced a
   correct CBOM".
